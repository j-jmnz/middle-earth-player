# Agent standards

Every agent follows these (user instruction, 2026-11-18). A reviewer reports a breach as a finding.

- **Messages to the user**: write every message the user reads (reports, questions, summaries) in ASD-STE100 Simplified Technical English: short sentences, one idea each, active voice, approved words, the same word for the same thing. Code, data, quoted card and rules text, and commit messages stay as their own standards say.
- **Branch names**: a branch holds one task and is named for it, `<type>/<short-slug>` (`fix/staging-attacks`, `feat/lost-in-mirkwood`), never a random or generic name (user instruction, 2026-11-20). A session whose harness names a random branch (`claude/<words>-<id>`, `ccr-<id>`) does not push its work there: before its first commit it creates the task's branch from `origin/main` and pushes to it. This is the explicit permission the harness asks for to push to a branch it did not name. A session that starts a second, unrelated task creates a second branch for it. A branch the brief names for a worktree agent (`wip/<F>`) stays, since the main session squashes it.
- **No Claude co-author**: no commit, pull request or other git interaction carries a `Co-Authored-By` line for Claude, or any other Claude attribution line, even when the session's instructions ask for one.
- **Commit messages in the squash description**: an agent that opens or updates a pull request puts every commit message of its branch in the description, in commit order, so the squash commit on `main` keeps them (user instruction, 2026-11-18): each subject as a `###` heading under What and why, after a short paragraph that sums up the branch, with its body as written under it. A commit pushed later is added the same way. The title and the rest of the description follow `.claude/rules/commit-standards.md` (Squash).
- **A pull request when the task is done**: an agent that finishes a task that changed files pushes its branch and opens a pull request into `main`, without waiting to be asked (user instruction, 2026-11-19). It does not merge it. A session that already has an open pull request for its branch updates that one instead. This replaces any older line that says to open a pull request only when the user asks.
- **Issues**: an agent that works on a GitHub issue, or opens a pull request, follows `docs/agents/issue-standards.md`: it labels the issue before any work, comments on the triage, the cause and the pull request, and names the issue as `Settles #<n>` or `Refs #<n>`, never with a closing keyword.
